# 格物 v1.3.1

**东西放在哪，你记得，它也记得。**

一套以「位置」为骨架、以「持有成本」为情绪回报的**纯本地**收纳记录工具 —— 物品分格管理、
到期提醒、照片记录。数据只在这台手机里，除主动点「找封面」外不联网，可从「我的 → 数据通道」导出备份包。

## 本版更新（相对 1.2.1）

这一版把几处**断掉的链路**接上了，另外修了几个数据层的真实缺陷。界面骨架没动。

- **多选之后能做的事多了两件** —— 除了原有的「补分类」，现在还能**批量改位置**和**批量删除**
  （删除走回收站，之后可整批恢复）。
- **手动排序终于有入口** —— 以前排序只是个要手打数字的字段，等于不存在；现在切到「手动」并清掉
  筛选，每行右侧出现 ↑ / ↓。
- **搜索变强** —— 能搜分类名、位置名、柜子名了；位置视图以前**根本没有搜索框**，这次补上。
- **导入备份前先给你看一眼** —— 只读预览：包里有什么、几件、什么时候备的、要怎么合。
- **修掉三个数据层缺陷** —— 合并导入的分类计数算错、覆盖导入留下孤儿照片、备份写入的级联风险。
- **界面留白修复** —— 录入页等三处卡片原本顶着屏幕两边（见下）。

<details>
<summary><b>展开：多选批量操作</b></summary>

长按任意物品进入多选后，底栏从一条动作变成三条：

- **补分类**（原有）
- **改位置** —— 搬家、换柜子、整理时一次改完一批，不必一件件进编辑页
- **删除** —— 走软删除进回收站，提示语明确写「移入回收站」而不是「永久删除」，
  删完可在「我的 → 整理 → 回收站」整批恢复

三者都包在一个事务里写库，避免批量操作写到一半失败留下半套数据。

</details>

<details>
<summary><b>展开：手动排序</b></summary>

`sortOrder` 字段、`manual` 排序档、行内「排序 N」标签其实一直都在，只是唯一的编辑入口是表单里
一个数字输入框 —— 让用户手打排序数字，等于这个功能不存在。

现在：把排序切到「手动」，**且没有搜索词、没有选中分类筛选**时，每行右侧出现 ↑ / ↓，点一下挪一格。

带搜索或筛选时不出现 —— 筛选后的顺序不是全量顺序，在那上面调顺序没有意义。

> 仍未做：长按拖动排序。现在是「点一下挪一格」，整段重排时要连点多次。

</details>

<details>
<summary><b>展开：搜索</b></summary>

- 搜**分类名**能搜到了：搜「药品」会列出归在药品类里的东西
- 搜**位置名 / 柜子名**也能搜到：搜「书房」会列出书房柜子里的东西（父级柜名一并匹配）
- 「我的物品」页搜索框占位符改为「搜索名称 / 品牌 / 分类 / 位置」
- **位置视图（柜子列表）以前完全没有搜索框**，这次补上，占位符「搜索柜子或格位」

> 仍未做：拼音 / 首字母搜索（`cdx` 还搜不到「充电线」）、搜索历史。

</details>

<details>
<summary><b>展开：导入前预览</b></summary>

以前导入备份是**盲选**：点了就导，不知道包里是什么、有几件、什么时候备的。

现在先弹一个**只读**预览（只读包、不写库）：

- 这份备份包里有什么
- 备份时间
- 本机现有的 N 件物品，要怎么合（**合并** / **覆盖**）
- 选「覆盖」会再确认一次，并把**要抹掉的数字写出来** —— 这个操作不可撤销

</details>

<details>
<summary><b>展开：三个数据层缺陷（本版最该升的理由）</b></summary>

**1 · 合并导入的「分类 N 个」是错的**

旧代码用「四个循环累加后的最终跳过数」去减分类数，而分类循环是**最先跑的**。
于是任何一次合并导入只要跳过过物品或照片，报出来的分类数就是错的，极端情况会算出**负数**。
现在改成分类循环自己的快照。

**2 · 覆盖导入会留下「孤儿照片」**

旧实现只删数据库里的行，**不删磁盘文件**。本地原有、但不在备份包里的照片会永远留在应用里 ——
用户看不见，但「占用 X MB」会把它算进去，空间显示无解释地偏大。
现在导入收尾统一对账一次，清掉没人引用的照片文件。

**3 · 备份写入的级联风险**

`insertRaw` 等四处用了 `INSERT OR REPLACE`，而照片表挂在物品表上有 `ON DELETE CASCADE`。
`REPLACE` 的语义是**先删后插**，一旦对已存在的物品触发，会静默删掉它已有的照片记录。
常规路径被 `existingIds` 挡住了，属潜伏雷。现在四处都改成显式的 `ON CONFLICT(id) DO UPDATE SET`。

</details>

<details>
<summary><b>展开：界面留白修复</b></summary>

**录入页的卡片（必填 / 归类 / 时间与花费 / 更多信息）原本顶着屏幕两边**，左右一点留白都没有。

根因：分组卡片组件只给「标题」加左右边距，**内容区是裸露的** —— 卡片要不要内缩全看每个调用点自己写。
全工程 14 处用到它的地方，有六处一处都没写。

顺手查出**不止录入页**，另外两处也一样漏：

- 录入页（四张卡）
- 新建柜子页
- 物品详情页的「备注」和「照片」两张卡

现在这几处的卡片左边框都在屏幕左缘 **17px**，与其他页面一致。

</details>

<details>
<summary><b>展开：性能与工程侧</b></summary>

**用户能感觉到的**

- 搜索加 200ms 防抖 —— 以前每敲一个字就查一次数据库
- 列表里的照片张数与封面改成一次联表查询 —— 以前每行两个相关子查询，N 行就是 2N 次
- 首页不再在启动时查柜子列表，切到「位置」视图才查
- 备份超过 30 天会主动催办（「我的」页那张品牌色卡片文案会变）

**工程侧（用户可忽略）**

- 移除 5 个装了但从没用过的依赖（`@expo/ui`、`expo-glass-effect`、`expo-symbols`、
  `expo-web-browser`、`expo-device`），包体比 1.2.1 小约 91 KB
- 补上 48 个纯函数单测（`node:test`，覆盖日期 / 金额 / 分类猜测 / 搜索拼装 / 建表迁移）
- 新增硬编码颜色守护脚本，挂进校验链
- **版本号改为单一来源**：`app.json` 是唯一真相，`build.gradle` 构建时现读它。
  以前两边各存一份，曾漏同步过一次（`app.json` 已是 1.0.0，manifest 还停在 versionCode 1，
  构建不报错、只打出自相矛盾的包）
- 清理空目录、7 个死函数、归档历史脚本到 `tools/_archive/`

</details>

## 安装

**方式一 · 手机上直接安装（推荐）**

1. 把 APK 传到手机（微信 / QQ 文件传输、数据线、网盘均可）
2. 在手机上点开这个文件
3. 系统提示「未知来源」时允许安装：
   设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选中你用来打开该文件的 App → 允许
4. 安装完成后桌面出现「格物」图标

**方式二 · 数据线 + adb**

```bash
adb install -r gewu-v1.3.1-arm64.apk
```

若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（之前用 Expo Go，或用了另一套签名装过同名应用），
先 `adb uninstall com.gewu.app` 再装。

> **注意：卸载会一并清掉应用内全部数据**（物品、照片）。需要保留的话先在「我的」里导出备份包，
> 装完再导入。**覆盖安装（不加 uninstall）则不受影响。**

<details>
<summary><b>覆盖升级须知</b>（为什么必须用同一把密钥签名）</summary>

安装包使用**自有签名密钥**（`android/app/gewu-release.keystore`）。以后发布新版本必须继续用
同一把密钥签名，否则手机无法覆盖安装，只能先卸载旧版 —— 而卸载会丢数据。

密钥与口令备份在工作区的 `gewu-签名密钥信息.txt`，**该文件不入库、不外发**。
仓库里只保留格式模板 `android/key.properties.example`。

</details>
