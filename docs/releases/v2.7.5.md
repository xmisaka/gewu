# v2.7.5 发布说明（2026-10-24 晚）

**列表首行空白 · 第二轮修复（换了实现）**

v2.7.4 只关了列表的回收开关，症状仍在。这一版去掉的是另一层裁剪。

## 复现（用户录屏 6.6 秒）

1. 「用完」+ 分类「全部」→ 白卡占两行，只显示第二行（猫砂），**第一行空白**
2. 切「全部 96」→ 正常
3. 点分类「宠物」（剩 1 条）→ 正常
4. 点回「全部」（又 2 条）→ **再次空白**

规律：每次都是「筛选结果变回 2 条」之后出现，96 条时首行正常。

## 像素证据

对录屏帧做采样（480×1044）：

- 空白区 `(240, 600)` = **`#FFFFFF`** —— 卡片白，不是页面米色 `#F9F8F4`
- 从卡顶 `y=560` 到内容 `y=697` **连续纯白、没有任何分隔线**
- 空白高度 ≈ 一个标准行（79dp）

结论：**cell 外壳（白底、边框、高度）在，`ItemRow` 子树没画。** 不是「数据只查出一条」
（那样卡片会缩成一行高），也不是「画在视口外」。

## 上一版为什么没修好

v2.7.4 关的是 `FlatList` 的 `removeClippedSubviews`（Android 默认 `true`）。
那确实是「摘掉原生子视图、不改布局」的一条路径 —— 但它不是唯一的一条。

这一版去掉的是**另一层裁剪**：`rowShellFirst` / `rowShellLast` 上的
`overflow: 'hidden'`。它的本意是让首末行的直角白底被圆角裁掉，但在 Android 上
同样是一层**离屏裁剪**，症状与前一层完全一样。

## 改法：圆角归行自己画

- `ItemRow` 新增 `cardFirst` / `cardLast` 两个 prop，首末行各自画
  `borderTopLeftRadius` / `borderTopRightRadius`、`borderBottomLeft/RightRadius`
  （半径同 `Radius.card`，与 `rowShell` 的边框圆角严格一致，不会露白角）
- `rowShellFirst` / `rowShellLast` **不再有 `overflow`**，只保留边框与圆角
- 有背景色的元素自己承担圆角 —— 这是不需要裁剪任何人的写法，从结构上就消除了
  「内容被静默裁掉」的可能
- `removeClippedSubviews={false}` 保留（那一层也确实是隐患）

**视觉零变化**：四角、边框、行距照旧。别的页面（到期、柜子、回收站）用同一个
`ItemRow` 但不传这两个 prop，完全不受影响 —— 所以它们默认必须是 `undefined`。

## 验证

- 测试 **703 → 705**（`tests/list-clipping.test.mjs` +2）：
  首末行壳不许出现 `overflow` / 首页必须把首末行告诉 `ItemRow`（且半径是 `Radius.card`）
- 变异 **2/2**：加回 `overflow` → 红；去掉 `cardFirst` → 红
- `npm run verify` 705 条全绿
- 差分（基线 `baseline-v274-r1`，md5 `ddc9951c…` = 19:30 上线的 v2.7.4）：
  bundle 4,655,372 → 4,655,648（**+276**），sha256 `d412a8c5… → 302b71ce…`
  - 净新增 2 项（0 → 1）：`cardFirst` / `cardLast`
  - 对照 6 项全 1→1：`长按缩略图可换封面` / `coverBadge` / `thumbHint` /
    `thumbActive` / `添加照片` / `removeClippedSubviews`
    （前四项是上一版的正向串 —— 它们必须还在，顺带证明基线没挑错）
- 权限 **12 条**与 v2.7.4 逐条一致；versionCode 38 / versionName 2.7.5
