# 格物 v2.6.0

**东西放在哪，你记得，它也记得。**

一套以「位置」为骨架、以「持有成本」为情绪回报的**纯本地**收纳记录工具 —— 物品分格管理、
到期提醒、照片记录。数据只在这台手机里，除你主动打开的能力外不联网，可从「我的 → 数据通道」导出备份包。

> **这一版做三件事：新增「家庭财产清册」、把会员权益重划一遍、再把界面文案重写一遍。**
>
> **清册**是这个 App 第一次产出「能交出去的东西」：三种 A4 版式，一次出 PDF 与 HTML，
> 可以直接发给自己、发给家人、发给要做财产公证的人。
>
> **权益**只动了分界线，没动价格（还是 ¥36 一次买断）：免费档从「不限件数」变成 **150 件**；
> **单张识物与语音录入**从支持者档挪到免费档；**清册**落在支持者档。
>
> **文案**是把「AI 味儿」洗掉：界面文案 828 条 / 10,833 字 → 865 条 / 9,296 字（−14.2%），
> 超过 40 字的长句 53 条 → 3 条，破折号「——」26 处 → 0。

## 这一版做了什么

### 一、新增：家庭财产清册（支持者档）

「我的」页多一行「家庭财产清册」。选一种版式，点生成，得到**两个文件**：

| | |
|---|---|
| **PDF** | A4、可直接发出去、直接打印 |
| **HTML** | 同一个排版，浏览器打开即可看，也能自己再打 |

**三种版式，卖的是品相：**

- **卷宗** —— 正式、可归档，末页带签署栏
- **账簿** —— 行距宽，留白是给人拿笔往上补的（这是账簿版的全部意义）
- **活页** —— 最紧凑，附位置索引与应急联

**三条口径是刻意定死的：**

**① 合计金额＝单件价相加，绝不乘数量。**
和首页统计卡用的是**同一个公式**（`lib/stats.ts` 的 `summarize()`）。清册若为了「更准」
把数量乘进去，用户会看到清册 ¥387、首页 ¥129，然后不再相信任何一个数字。
数量以 `×N` 标在名称前 —— 一眼看得出「这一行只算了一件」。

**② 库里没有的字段，清册不印。**
序列号、保单号、现估值、产权人：库里没有这几列，所以册子上就没有这些栏目。
为少数高价值品给每件物品的表单加两行，成本会摊到所有用户头上 ——
需要手填的，账簿版给了留白页。

**③ 只做「发送」，不做「打印」。**
两个文件各自带一行「发送」，走系统分享面板（微信、邮箱、存到手机都行）。
刻意**没有**做 App 内打印：打印引擎在安卓上要拉系统打印服务，
出一条打印预览的岔路，等于让「生成好了但发不出去」这种情况再翻一倍。

**顺手修掉的两处静默失败**（都是打样时真踩到的）：

- **文件名精确到秒。** 原来只到分钟，同一分钟内再点一次会撞名，而
  `expo-file-system` 的改名**没有覆盖语义** —— 用户看到的是
  「生成成功，发送失败」外加一串 `FileAlreadyExistsException`。
  现在文件名带秒，写盘时再用 `overwrite: true` 兜一道：一道管「几乎不会撞」，一道管「撞了也不炸」。
- **每个单元格都包 `<span class="c">`。** 少了它，长名字会折成两行、行高被撑开，
  实际能放的行数少于计划，多出来的行被 `overflow:hidden` **静默切掉**
  （实测 34 行就吃满一页，而计划是 30 行）。现在有一条源码级断言守着 `<td>` 与 `class="c"` 的数量关系。

所有用户数据一律转义 —— 物品名叫 `A<B`、备注里有 `&`，不转义会把后面整段吃掉，
看起来只是「少了几行」。

### 二、会员权益重划：一条线往上、一条线往下

| | 免费档 | 支持者档（¥36 一次买断） |
|---|---|---|
| 物品件数 | **150 件** | 不限 |
| 收纳 / 搜索 / 标签 | 有 | 有 |
| 到期提醒 / 库存 | 有 | 有 |
| 照片 / 备份恢复 / CSV 导出 | 有 | 有 |
| 单张识物、语音录入 | **有（本版放开）** | 有 |
| 批量识图、问一问 | — | 有 |
| 统计洞察 | — | 有 |
| 家庭财产清册 | — | **有（本版新增）** |
| 主题皮肤 | 素笺 / 靛青 / 青瓷 | 再加朱砂 / 藕荷 / 胭脂 |

**为什么把识物和语音放下来。** 这两件事各是一步操作，用户试一次就知道价值；
锁在门后，他连「值不值得买」都判断不了。真正花钱买的是**批量**（一次九张）和**问答**
（让模型把本机事实说成人话）—— 那是「一次省半小时」，不是「一次省三十秒」。

**为什么清册收在支持者档。** 清册卖的是**版式与打印品相**，不是「把数据带走」。
**CSV 导出仍然免费** —— 那才是「带走自己的数据」，这件事不能按次收费，它是用户的底线。

**150 件为什么是 150。** 按实测库容量定的线：一个普通家庭认真记满整屋东西，
大致落在 100~150 之间。定在 150，是让「真在用」的人踩不到它；定在 50，
会变成「试到一半被拦下来」。**到顶之后也没有断供**：已有的东西照样能查、能改、能删、
能导出、能备份，只是不能再新增。

三条实现口径写死在代码注释里（`src/lib/entitlement.ts`），也写在这里：

**① 判的是「这一次要存几件」，不是「满了没有」。**
`checkNewItems(used, incoming, entitled)` 收的是本批件数。剩 3 件额度时选 9 张批量识图，
会**整批挡住**并说明原因 —— 不会半推半就地存下 3 件，让用户以为另外 6 件也进去了。

**② 只挡新增，从不回溯。**
`countItems()` 每次现查库里的真实条数，不做「满没满」的缓存判断。
已经记了 300 件的老用户不会因为这次更新被锁在任何一页之外。

**③ 四条新增路径共用同一道闸门。**
录入 / 批量识图 / 语音 / 复制一件 —— 四份代码、四种表单，各写一遍必然漏一处。
现在统一走 `lib/hooks/use-quota.ts` 的 `useQuotaGuard()`：
**额度不够时只提示，不抛错**（表单的 `onSubmit` 是裸 `await`，抛出去就是未捕获异常）。

### 三、界面文案统一精简

同一把尺子量下来（只统计含中文的字符串字面量）：

| | 改前 | 改后 |
|---|---|---|
| 条数 | 828 | 865 |
| 总字数 | 10,833 | 9,296（**−14.2%**） |
| 超过 40 字的长句 | 53 | 3 |
| 破折号「——」 | 26 | 0 |

留下的 3 条长句是刻意的：删除确认、两处权益说明 —— 那些句子长是因为**后果说清楚了**，
砍短反而会让人误操作。

具体做法只有四条：

- **一句话说一件事。** 「免费档的字一个字没动。另外之前那版提到的 XXX 也不受影响，
  见下面的说明」→「免费档照旧」。
- **删掉自我解释。** 界面上不解释「为什么这么设计」，那是注释和这份文档该待的地方。
- **破折号归零。** 「——」在中文里是作者的手势，在按钮下面就是噪音；该断句就断句。
- **同一句话只写一遍。** 「免费档照旧」原先在批次页、问一问页、语音页各写一遍，
  现在只留在门控浮层与说明页。

**顺手修掉一处真 bug**：AI 设置页原先把一段开发者备注（以「★」开头、
结尾还写着「见 ROADMAP 的口径记录」）当作正文渲染给了用户。它藏在被删掉的整页锁定分支里，
一放开就露出来了。

## 老数据与档位

- **老数据一条不动。** 这一版没有数据库迁移，schema 与 v2.5.1 完全一致。

- **已激活的支持者权益不变。** 清册是「加进来」的，原本就在支持者档里的人不会丢任何一项。

## 已知的边界

- **清册没有「打印」按钮。** 只出 PDF 与 HTML，打印交给系统或浏览器（见上「③」）。
- **清册不写序列号 / 保单号 / 现估值。** 库里没有这些列，册上就不印 —— 账簿版给了留白页。
- **清册的 HTML 附件在微信里能否直接发出去未验。** 若被拒，入口会改成「存到手机」。
- **没有「试用」这个档。** 150 件是硬线，到顶后只提示、不降级、不软锁 ——
  免费档仍是完整版，只是不能无限长。
- **文案尺子是静态扫描，不是跑起来量的。** 它挡的是「写进源码的长句」；
  拼出来的句子（模板串跨行、运行时拼接）只能靠人工复核，这一轮已逐条看过。
- **弹窗写了 4 条**（App 的更新弹窗上限就是 4 条）：清册、识物语音免费、150 件上限、
  文案精简。完整历史一直在官网页 `changelog.html` 上。
