# 格物 v1.4.0

**东西放在哪，你记得，它也记得。**

一套以「位置」为骨架、以「持有成本」为情绪回报的**纯本地**收纳记录工具 —— 物品分格管理、
到期提醒、照片记录。数据只在这台手机里，除主动点「找封面」外不联网，可从「我的 → 数据通道」导出备份包。

## 本版更新（相对 1.3.1）

这一版补的是 PRD 里白纸黑字写过、但一直没兑现的三件事。界面骨架没动，不会有陌生的感觉，
但三处以前做不到的事现在能做了。**三件都不碰数据库结构、也没有引入新依赖。**

- **分类管理** —— 以前分类是「出生即固定」的：十四个内置分类改不了、加不了、删不掉。
  现在「我的 → 整理 → 分类管理」可以新建 / 改名 / 排序 / 删除，默认保质期也收在这里。
- **一键复制物品** —— 同款买第二个（线材、杯子、收纳盒）以前要全部重填。
  现在详情页底部有「复制为新物品」，带过名称 / 分类 / 位置 / 品牌 / 单价。
- **定时自动备份** —— 以前只有手动备份 + 超期提醒，而 PRD 两次写明「必须定时自动执行」。
  现在启动时自己判断，静默写一份回滚副本到本机；顺带把只增不减的本地备份包做了两层封顶。

<details>
<summary><b>展开：分类管理（本版最大的一块）</b></summary>

在这之前，分类是「出生即固定」的 —— 十四个内置分类改不了、加不了、删不掉，
界面上唯一能做的是从已有分类里挑一个。想加「相机镜头」「露营装备」这类自己的分类？做不到。

现在：「我的」→「整理」→「分类管理」。这一页能做四件事：

- **新建分类**
- **改名**
- **排序** —— 行右侧的 ↑ / ↓，顺序就是首页筛选条的先后
- **删除**

并且把「默认保质期」收在了这里 —— 以前它是录入页里写死的，现在改了这一页，
录入时按分类带出的保质期就跟着变。

三条写在界面上的规矩：

1. **内置分类不可删除，但可以改名。** 猜词要靠内置分类挂靠，可「数码」「五金」未必贴合
   每个人的生活，所以允许改名 —— 改的时候会亮一行琥珀色提示，说明改名后这一类不再自动猜中
   （猜词词典按种子原名建索引），不藏着。
2. **删除前会检查这一分类下还有没有东西**，有的话提示先把它下面的 N 件改到别的分类，
   不会连坐删掉物品。
3. **分类名不允许重名**（大小写不敏感，所以 `USB` / `usb` 算同一个）。因为分类名是猜词词典的
   业务键，重名会让猜测结果变得不确定。

> ★ 一个必须跟着改的连带项：内置分类的种子数据以前是「按名字补齐」的，现在改成
> 「**分类表为空时才灌一次**」。否则用户把「数码」改名成「电子产品」，下次启动会把「数码」
> 重新塞回来，猜词也会跟着错位。

</details>

<details>
<summary><b>展开：一键复制物品</b></summary>

同款买第二个（线材、杯子、收纳盒）是很常见的录入场景，以前要把名称、分类、位置、品牌、
单价全部重填一遍 —— 正是 PRD 点名要防的「录入疲劳」。

现在：物品详情页底部多了一个「**复制为新物品**」。它会带过 **名称、分类、位置、品牌、单价**，
跳到录入页让你确认后保存，存完落到**新物品的详情页**（不是回到原物品），方便你核对。

**照片和备注不会带过来**，这是刻意的 —— 两个副本共用一份图的话，删掉其中一个，另一个就会
变成白框。复制出来的是「一件新的同类物品」，不是「同一件东西的第二份记录」。

> 实现上没有复用编辑页：编辑是**差量更新**，复制是**新建**，两者的提交语义不同，
> 共用最易出错的正是照片的归属。字段走的是显式白名单，将来加字段默认「不被复制」。

</details>

<details>
<summary><b>展开：定时自动备份 + 历史备份包清理</b></summary>

PRD 在风险清单里把这件事写了两遍「必须」，其中一句是原话：

> 「需要手动触发的备份最终会被弃用，必须定时自动执行」

而在这之前，格物只有手动备份 + 超期提醒 —— 等于把 PRD 判定会失败的模式原样实现了。

现在：App 启动时自己判断一次，「距上次备份超过 7 天、且这期间数据有变更」就静默写一份
备份包到应用自己的缓存目录。**不需要新权限、也不需要后台运行**，不打扰你。

「我的」页会多一行小字说明自动备份的状态，比如「已于 3 天前存到本机」。
首次大概率不会立刻触发 —— 要么没到 7 天，要么数据这期间没变过，这是正常的
（不重复写同样的包）。

> ★ 自动备份和手动备份**故意分两行显示，不合并**：自动那份只是本机缓存里的一份回滚副本
> （手机丢了照样没）；手动那份要**包离开了手机**（发到微信、存进网盘）才算真防丢。
> 合并成一行会让人误以为「App 已经帮我防丢了」。

顺带做掉的一件事 —— **本地备份包清理**：缓存目录里的包以前只增不减，每个包约等于一次全量
快照（含全部照片）。现在有两层封顶：**最多留 3 份，且总量不超过 400 MB，但至少留一份**。
「我的」页的数据通道卡里多一行「清理本地备份包 N 个 · X MB」，点它可以直接手动清
（手动清理更狠，只留最新的一份）。这一行只在真的存在备份包时才出现。

</details>

<details>
<summary><b>展开：工程侧（用户可忽略）</b></summary>

- **把「判该不该备份」抽成纯函数**（`src/lib/backup/policy.ts`，不 import 任何 RN 模块）——
  判太松会天天写包，判太紧等于永远不写；保留策略多留一份是存储炸弹，多删一份不可逆。
  这类逻辑**判错不报错**，只能靠单测兜住，所以单独拆出来。
- **数据指纹只用 6 个标量查询**（物品 / 回收站 / 分类 / 位置 / 照片计数 + 最晚修改时间），
  不为自动备份引入全表扫描。
- **打包前检查可用空间**，不足直接跳过，不把手机写满。
- 单测从 **54 条加到 67 条**；新增的都在 `tests/policy.test.mjs`（13 条），覆盖
  「空库不备 / 从没备过 / 未到间隔 / 已到间隔且数据变了 / 指纹没变 / 旧版本无指纹 /
  未来时间戳」以及保留策略的四种边界。
- 设计稿同步到**十屏**（新增「分类管理」屏），截图重新导出。
- 校验链仍是 `npm run verify` = lint + typecheck + 硬编码颜色审计 + 单测。

</details>

## 安装

**方式一 · 手机上直接安装（推荐）**

1. 把 APK 传到手机（微信 / QQ 文件传输、数据线、网盘均可）
2. 在手机上点开这个文件
3. 系统提示「未知来源」时允许安装：
   设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选中你用来打开该文件的 App → 允许
4. 安装完成后桌面出现「格物」图标

**方式二 · 数据线 + adb**

```bash
adb install -r gewu-v1.4.0-arm64.apk
```

若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（之前用 Expo Go，或用了另一套签名装过同名应用），
先 `adb uninstall com.gewu.app` 再装。

> **注意：卸载会一并清掉应用内全部数据**（物品、照片）。需要保留的话先在「我的」里导出备份包，
> 装完再导入。**覆盖安装（不加 uninstall）则不受影响。**

<details>
<summary><b>覆盖升级须知</b>（为什么必须用同一把密钥签名）</summary>

安装包使用**自有签名密钥**（`android/app/gewu-release.keystore`）。以后发布新版本必须继续用
同一把密钥签名，否则手机无法覆盖安装，只能先卸载旧版 —— 而卸载会丢数据。

本次签名证书 SHA-256 `caedfd4b…a9983f`，与 1.2.0 / 1.2.1 / 1.3.1 是同一把，可以直接覆盖安装。

密钥与口令备份在工作区的 `gewu-签名密钥信息.txt`，**该文件不入库、不外发**。
仓库里只保留格式模板 `android/key.properties.example`。

</details>
