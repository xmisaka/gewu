## 本版更新（相对 1.4.1）

这一版给物品补上「**还剩几件**」。

以前格物只知道一件东西「有没有过期」，不知道「还有没有余量」—— 快用完的东西
照样安安静静躺在列表里，直到某天要用才发现没了。本版把它补上，并且**全程没有
在列表行上放任何能改数量的按钮**：数量是会被误触的，列表又是最容易误触的地方。

- **录入时可选填「数量」** —— 留空就是单件物品（默认，也是绝大多数情形）。
  数量 `0` 和「没填」不是一回事：`0` 是「这一批用完了」，没填是「它本来就只有一件」。
- **列表行尾一个只读的余量胶囊** —— 只有填过数量的物品才显示：`剩 3` / `剩 1`（琥珀色）/
  `用完了`（暗红）。它只是给眼睛看的，点它**不会**直接改数字。
- **点胶囊弹出底部快捷面板** —— 「用掉一件」/「补一件」两个大按钮，**按完不自动关**
  （可以连点），关掉之后底部才浮出一条撤销条，几秒后自动消失。
- **详情页库存卡** —— 启用了数量的物品，在照片正下方、持有成本卡之上，显示
  剩余件数 + 状态词 + 单件价说明。
- **提醒页新增「该补货了」分组** —— 快用完的东西出现在最前面，行尾带「补货 +」，
  点一下就地加 1。

<details>
<summary><b>展开：为什么「数量」要放在列表行尾，却不给它控件</b></summary>

最初做过一版「把加减直接放到列表页」的交互（行内胶囊 + −1 圆钮、行内步进器），
**被打回**，理由是六个字：

> 「数量加减直接放到列表页，不美观，而且容易误触。」

这个判断是对的，而且改掉的不只是「好不好看」：

- 列表是**浏览**的场所，手指在这里主要在做滑动。在这一层放一个「按一下数字就变」的
  东西，等于把一个**会改数据的控件塞进最容易误触的位置**。
- 加减一旦在行上，就没有「确认」这一步 —— 减错了、减多了，用户得自己发现。
- 行尾本来就窄，塞进两个按钮会把「名称 + 位置 + 价格 + 余量」挤成一团。

最终形态是「**只读胶囊 + 底部面板**」：列表行上永远只有一个看的东西（`剩 1`），
改数量的动作全部推进面板里。面板按完不关、关掉之后才浮撤销条 —— 这一条是刻意的，
连点几下也不会被撤销条挡住手指。

> 实现上，面板是**独立组件** `StockSheet.tsx`，不塞进 `ItemRow`。
> 原因：列表是虚拟化的，行会随滚动挂载/卸载，把有状态的浮层挂在行里，
> 滚出去再滚回来状态就乱了。

</details>

<details>
<summary><b>展开：「单件价」口径（本版最容易踩的一处语义）</b></summary>

「单价」字段**锁死为单件价**，数量**不参与任何计算** —— 日均持有成本、资产总额
都还是按单件价算，**公式一个字都没改**。

买六瓶同批次酱油（单件 15.8 元），记「一条记录 + 数量 6 + 单价 15.8」，
**不是**记总价 94.8。两条理由：

1. 数量会被一瓶瓶消耗掉。按总价算，资产的「总额」会随着你喝酱油而上下跳动 ——
   数据反而比不算更乱。
2. 与「按次成本」那套摊销口径纠缠。两套算法各按各的基准，混起来谁也说不清。

> 与此相关的一条交互细节：**改数量不会更新「最近修改时间」**。
> 数量变化是「消耗」，不是「这件东西的信息变了」—— 让它去刷新列表排序，
> 会让「最近动过」这个视图整个失真。

</details>

<details>
<summary><b>展开：为什么同名物品还是默认分开记（v1.5.0 补的例外条款）</b></summary>

有了数量字段之后，一个老问题会被重新提起：**六根线材，到底记六条还是记一条数量 6？**

PRD 的原则没变，本版补了一条例外，判据只有一句：

> **判断依据始终是「过期时间是否相同」，不是「是否同款」。**

| 情形 | 记法 | 理由 |
|---|---|---|
| 六根 Type-C 线 | **六条** | 各有位置与使用寿命，需要单独定位、单独判断 |
| 六瓶同批次酱油（保质期相同） | **一条 + 数量 6** | 过期时间相同；拆成六条会产生六份完全重复的字段 |
| 六瓶药品（生产批次不同） | **六条** | 过期时间只有一个字段，合并会掩盖批次差异、导致剩下几瓶失管 |

也就是说：数量字段是给「**同一批、同一个到期日**」的东西准备的，不是用来
「把同款合并成一条」。药品这种最需要盯到期的东西，恰恰是**不应该**合并的那一类。

</details>

<details>
<summary><b>展开：提醒页的两个「件数」不是一个数（角标口径修正）</b></summary>

本版顺带修了一个口径漏洞。提醒页此前用的是「到期口径」的件数，加了「该补货了」
这一组之后，如果继续沿用，就会出现：**标签栏角标显示 3，点进去却能数出 4 行。**

现在把两个口径分开：

| 口径 | 含义 | 用在哪 |
|---|---|---|
| `expiringCount` | 到期口径：快到期 + 已过期 | 首页统计卡的「即将到期」 |
| `attentionCount` | 待办口径：快到期 ∪ **该补货**，**去重** | 提醒页副标题 + 标签栏角标 |

关键是**去重**：一件东西既快过期、又只剩 1 件，只算一次。实现上这条必须
**用一个 SQL 里的 `OR` 写** —— 分成两次查询再相加，就会把「既过期又只剩 1」
的那件算两遍。

> 首页统计卡的标签写的就是「即将到期」，所以它**不能**混进库存数，否则标签会说谎；
> 角标是「有几件事要去看」，所以它**必须**等于提醒页里能数出来的行数。

</details>

<details>
<summary><b>展开：工程侧（用户可忽略）</b></summary>

- **数据库迁移三段分离**：建表 → `migrate()` → **建索引**。索引必须排在迁移之后 ——
  顺序反了，老库升级会撞 `no such column`，**整个库直接打不开**。迁移本身幂等，
  重复启动不会重复加列。
- **禁 `SELECT *`**：SQLite 里 `ALTER TABLE` 加的列排在表末尾，老库和新库的列序不同，
  按位置取值必然错位。代价是：以后再加列，必须同步补上视图的全部显式列名。
- **减法先读后写**：SQLite 的 `max()` 单参数是**聚合函数**、双参数才是标量。
  写混了两者不报错，但语义全变。所以数量减法统一走
  `Math.max(0, before + delta)`，并且顺带返回旧值供撤销条使用。
- **「用完了」是派生态**：`quantity === 0` 只在渲染时判定，**不落库**成一个状态字段 ——
  这样绕开了 PRD 里「不做状态机」的那条禁令。
- **两个文案函数分开**：`stockLabel()`（胶囊用：`剩 N` / `用完了`）与
  `stockStateText()`（卡片用：`还有余量` / `即将见底` / `已用完`）。同色不同词，
  混用会让一处改文案时另一处跟着变。
- 单测仍是 **82 条**全绿；校验链 `npm run verify` = lint + typecheck + 硬编码颜色审计 + 单测。
- 设计稿同步到**十二屏**（新增「库存快捷面板」「详情页库存卡」两屏），截图重新导出。

</details>

## 安装

**方式一 · 手机上直接安装（推荐）**

1. 把 APK 传到手机（微信 / QQ 文件传输、数据线、网盘均可）
2. 在手机上点开这个文件
3. 系统提示「未知来源」时允许安装：
   设置 → 应用 → 特殊应用权限 → 安装未知应用 → 选中你用来打开该文件的 App → 允许
4. 安装完成后桌面出现「格物」图标

**方式二 · 数据线 + adb**

```bash
adb install -r gewu-v1.5.0-arm64.apk
```

若报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（之前用 Expo Go，或用了另一套签名装过同名应用），
先 `adb uninstall com.gewu.app` 再装。

> **注意：卸载会一并清掉应用内全部数据**（物品、照片）。需要保留的话先在「我的」里导出备份包，
> 装完再导入。**覆盖安装（不加 uninstall）则不受影响** —— 本版的数据库迁移会在覆盖安装后
> 首次启动时自动完成，老数据不会丢。

<details>
<summary><b>覆盖升级须知</b>（为什么必须用同一把密钥签名）</summary>

安装包使用**自有签名密钥**（`android/app/gewu-release.keystore`）。以后发布新版本必须继续用
同一把密钥签名，否则手机无法覆盖安装，只能先卸载旧版 —— 而卸载会丢数据。

本次签名证书 SHA-256 `caedfd4b…a9983f`，与 1.2.0 / 1.2.1 / 1.3.1 / 1.4.0 / 1.4.1
是同一把，可以直接覆盖安装。

密钥与口令备份在工作区的 `gewu-签名密钥信息.txt`，**该文件不入库、不外发**。
仓库里只保留格式模板 `android/key.properties.example`。

</details>
