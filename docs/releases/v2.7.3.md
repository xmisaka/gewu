# v2.7.3 发布说明（2026-10-21）

**添加照片自己起相机 · 列表加库存档位**

两件事打在一个版本里。前一件是魅族用户报的 bug，后一件是产品补的口径。

## 一 · 添加照片不能拍照

### 根因

不是权限、也不是 bug —— 是**拍照这件事原来完全外包给了系统相册选择器**。

`pickFromLibrary()` → `launchImageLibraryAsync` → AndroidX `PickVisualMedia`
（`ACTION_PICK_IMAGES`，无实现时回落 `ACTION_OPEN_DOCUMENT`）。那条链上
**没有任何参数**能要求「给我一个相机入口」—— ImagePicker 的选项里就没这一项。

两张用户截图是两个不同的选择器：常见的那个第一格画着「相机」，Flyme 的只有
「照片 / 相册」两栏。那个相机格是 **ROM 自己画的**，各家用不用它自己决定。

`aapt2 dump badging` 也证明权限一直在包里（`android.permission.CAMERA`，
来自 expo-image-picker 原生模块的清单合并 —— 那个 config plugin 只在
`cameraPermission: false` 时**屏蔽**权限，从不主动添加）。

### 修法

`captureWithCamera()`（`ACTION_IMAGE_CAPTURE`）早就写了，但只被 AI 识物用。
现在「添加」也接上：先弹 `PhotoSourceSheet`（拍一张 / 从相册选），
两条路都汇到 `ingestPicked()`，压缩、缩略图、失败计数只有一份写法。

- **先关弹层再起相机**：Modal 在 Android 上是独立 Dialog 窗口，
  与相机 Activity 叠着时返回结果会丢（同 `runRecognize` 的做法）。
- 按钮图标 `camera-outline` → `add`：画着相机却进相册，本身就是误导。
- 识物那个弹层不动：目的不同（挂图 vs 认东西）。

## 二 · 列表加库存档位

原来只有一份列表，用完的东西和还有的混在一起 ——「我家有多少件东西」这个问题
永远说不清。现在顶部三档：**全部 / 还有 / 用完**，默认只看「还有」。

口径钉死在一处（`lib/stock.ts` 的 `stockWhereSql`，与 `stockState` 同一个文件）：

- `quantity IS NOT NULL AND quantity <= 0` = 用完；负数也算（历史脏数据）。
- **`quantity === null` 的单件物品永远算「还有」** —— 判错的症状是用户在
  「用完」里看见自己从没启用过库存的东西，而那件东西的详情页连
  「标记用完」都不显示，界面上没有任何地方能解释它。
- 两档互斥且穷尽：`还有 + 用完 = 总数`（「还有」用减法算，与 `fineCount` 同一手法）。

★★ **默认「还有」只写在首页的 state 里，数据层 `stock` 缺省是不筛。**
清册导出、统计页、分享、问一问都调同一个 `listItems` —— 数据层一旦默认筛掉
用完的，清册会**静默少几件**，而发出去的清册收不回来。

配套三处：

- `getStats()` 补 `inStockCount` / `usedUpCount`，三档胶囊带件数。
- `listCategories({ stock })`：分类胶囊的件数跟着档位走。不跟的话，
  默认档下每个分类都比自己列出的行多出几件，第一反应是「东西丢了」。
- `manualReorder` 守卫补 `stockFilter === 'all'`：漏了它，默认视图就能拖顺序，
  被「用完」挡在外面的那几件会永远卡在 `setManualOrder` 写回的序列之外。

界面上还有几条：库里一件都没用完时整排不出现（不给空入口，但已在非默认档上时必留）；
「用完」档空了说「没有用完的东西」而不是「没找到」；全部用完时默认档说
「东西都用完了」并给一个「看用完的」按钮。

文案顺手换两处：副标题 `在库 N 件 · 共 ¥X` → `共 N 件 · 价值 ¥X`，
统计卡 `在库` → `物品`。那个数字是**含用完**的总数，和「还有」不是一个口径，
不该共用一个词。统计页与海报里的「在库物品」没动 —— 那两处没有档位，
在库＝不在回收站，说法是准确的。
